\section{Conclusion}
\label{sec:conclusion}
A reusable code change can be authorized, pass its replay tests and still be wrong for the repository it is about to run on, and two
changes that are each beneficial can be jointly harmful.  We gave an admission rule whose error budget holds over a whole library,
over compositions and over re-admission; proved that its shift term cannot be removed and that individual risks say nothing useful
about composite risk; and tied certificates to what actually runs through an execution rule.  Pre-registered experiments, negative
results included, show where such a gate matters and where it does not: on our real skill targets harm was frequent and a simple gate
with target evidence sufficed, the certificate's distinctive behaviour being its refusal of changes that do not help; in LLM patches
partial harm exists but depends strongly on how harm is defined.
